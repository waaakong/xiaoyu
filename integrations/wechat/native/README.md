# 小鱼原生文字发送 · 0.22.0

当前适配：Windows x64 微信 4.2.0.13 的精确核心构建，SHA-256
`afe3d02c58bada3c35009c0cd58ee1f57b2a00fe53237d0dce649107fddb9a20`。
这是小鱼独立实现的文字发送 DLL，不包含 WeChat-Hook 源码或二进制，
不安装 version.dll 代理，不做隐藏、撤回或版本限制补丁。

## 实际能力

- 接收：沿用已经验证的独立数据库读取器和账号核验，不使用窗口读取。
- 发送：调用当前精确构建的原生文字路径，不搜索、激活、切换或输入窗口。
- 确认：提交成功与送达分开；仍通过独立读取器核对新增的服务器消息 ID。
- 前台方式保留，必须手动切换；未知投递不自动重发或改用其他方式。
- QQ 与微信保留各自联系人授权、人格和记忆库。

目前没有新增图片、语音、原生 @ 或进程内消息回调。数据库接收不能
描述为已经适配了所有消息回调。当前实测对象是文件传输助手，其他好友、
群聊仍遵守既有授权，并需要按实际使用范围验收。

## 使用与恢复

微信页的“启用小鱼原生文字”会停止微信接入、选择此组件并核验启动；
不改变聊天授权。启动时先验证本机微信、读取目录和当前进程，再检查
已经验证的 DLL、源文件和核心哈希。正常重连复用已验证会话，精确构建
或账号不匹配则拒绝加载。无法确认已有组件状态时不重复加载。

加载使用明确的目标 PID 和标准 LoadLibraryW；不修改微信安装文件、
系统权限、注册表或微信启动项。服务仅监听 127.0.0.1，以随机令牌访问。
令牌和加载状态只在本机 data 中保存，不随发行包发布。

在高级连接设置中选择“前台发送”即可回到原路径。卸载本次组件可使用：

```powershell
python scripts/load-wechat-native.py --stop
```

须使用已核验的独立 Python 运行环境。停止服务并确认工作线程退出后，
才调用 FreeLibrary，并检查模块确实消失。停止超时则拒绝卸载。
退出微信也会清除本次加载的模块；小鱼不会为此自动退出微信。

`5b63c8e8fba23bf9de6937e50e348b241ef7d2b13d408014abb01ae5fb9137e1`。

2026-11-06 已完成本机真实加载、健康检查及文件传输助手服务器回执核验。
直接提交至确认送达 269ms；通过小鱼完整投递路径为 387ms，包含

这是单机样本，不包含模型生成，也不代表所有聊天都已达到 QQ 总耗时。

`scripts/build-wechat-native.py` 用经官方哈希核验的 Zig 0.15.2 构建。
构建只读精确核心文件，生成本地 profile.h 和哈希清单，不执行加载。
`--offline-test` 生成另名模拟 DLL，不能调用微信；生产加载器明确拒绝它。
协议测试见 `test/wechat-native-bridge-test.py`，应用路径测试见
`test/wechat-native.test.js`。编译工具链不随应用打包。

构建产物仅随发行包带入生产 DLL、清单和不含账号/消息 ID 的验证摘要；
不包含模拟 DLL、PDB、编译器、实时会话令牌或数据库凭据。

运行时的来源与许可通知保存在 notices/：Zig（MIT）、MinGW-w64（ZPL及其
文件所述例外）。微信、Windows 和独立读取组件继续遵守各自条件。
