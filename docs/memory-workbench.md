# 记忆与人格工作台（0.17.1）

本版正式接入简笔画小鱼图标、无系统标题栏窗口、可自选本地背景的玻璃界面及GSAP短动效。关闭主窗口仍收起到托盘；托盘“退出并停止服务”才停止后台。减少动态效果及低性能模式均可在外观页设置。背景保留本机副本，不上传，也不移动原始图片。

## 已接入的真实数据

- 原有事实库、更正/遗忘、来源、逐事实跨聊天授权继续复用。
- 七类笔记：用户事实、表达反馈、持续项目、资料、共同经历、未来约定、角色设定。笔记按角色与聊天隔离，正文按相关性选择，与现有记忆共用原字符预算；不是全库注入。
- 手动记事本和MD/TXT资料导入。日记不会当成用户现实事实或跨角色经历。
- 人格草稿、基础版本、表达增量的提交/审核/撤回。基础卡变更后的旧候选不能批准；未批准项不影响回复。
- 原文关联、笔记版本、归档/恢复、遗忘及来源失效校验。新模型轮次写入角色与运行编号；旧记录保持“未记录”，不倒推。
- 实际用量、p50/p95耗时、召回轨迹、审计和一致性SQLite备份。页面数字来自本机记录，最多展示近期1000条调用，不估算费用或宣称节省比例。

## 后台整理

默认全部关闭。可以按聊天开启新增消息的成长候选或自动日记，也可手动运行。任务单并发；自动任务需30条新增有效用户消息、至少空闲60秒、间隔30分钟；每日最多4次和20000 token准入估计。实际返回用量另行记账，取消或缺失用量按估计保守占额，不承诺取消后云端零消耗。前台消息会取消后台任务。日记只使用已记录角色身份的对话，不把旧聊天归给当前角色。

成长项需本机审核；自动日记只写本机笔记，不自动向QQ发布。原始文字经召回或整理进入模型上下文后，仍交给当前配置的云模型。

## 插件协调

已核对AstrBot 4.29.4按事件选择插件的接口。小鱼带有效事件租约的增强流程会跳过Angel Memory、LivingMemory、Self Learning的重复记忆/学习处理；其余聊天和插件全局开关不变，chat_plus保留。脚本不改第三方插件源码或数据库。已有插件数据没有自动合并进小鱼；本机检查时三个插件的可迁移记忆/审核表为空或未初始化。

## 本版限制与后续阶段

可选神经语义模型的下载和向量融合、实体关系图谱、第三方插件历史数据的格式化导入/撤回、完整模拟状态轨迹仍未实现。当前使用现有词法召回及有界笔记选择；不把未启用语义层称为召回成功。主动消息仍关闭。本版不是完整R4方案全部高级能力的完成声明。

自动化验证覆盖数据隔离、候选审核、版本失效、删除、后台取消/预算、图片副本及应用接口；原生窗口已编译并实际启动。用户已确认最大化、还原、最小化和关闭后托盘恢复均正常；多屏缩放仍未验证。

## 全聊天固定记忆与遗忘边界

人工固定记忆独立存储于各平台的fixed_memories表。普通聊天、增强回复和人格问候预览统一注入，不依赖关键词召回，不受记忆字符预算或摘要压缩影响，不由自动事实提取更新。关系称呼绑定平台账号ID，昵称相同或聊天自称不能认领，也不授予管理权限。记忆库与“状态与情绪”页显示固定内容。QQ、微信分别保存配置，其他记忆仍不互通。

全量重置在停止旧任务后进行，先生成本机数据库快照，再清理事实、版本、摘要、笔记、共享事实、学习候选和召回记录。旧聊天保留显示，但通过持久化消息边界和封锁表退出上下文、引用、历史检索、跨聊及学习；索引维护不会重新引入。保留联系人、素材、授权与续聊连接结构，新消息可重新积累记忆。重置函数需要明确确认参数，不开放远程聊天调用。

## 状态与情绪

“状态与情绪”页显示电脑CPU/内存/开机时间、指定程序的进程观测，以及小鱼、Codex、DSH、QQ、微信、插件的连接与最近失败/恢复事件。进程每10秒采样，超过30秒未成功采样标记过期；进程运行不能证明账号在线。事件仅保留最近200条类别和时间，可暂停与清理；不采集屏幕、窗口标题、剪贴板或完整进程命令行。电脑资源详情仅本机显示，远程聊天在相关问题中获得当前平台和模型服务的最小状态与最近事件，不获其他平台的聊天内容或电脑资源详情。

情绪按平台数据库、聊天和人格分别存储，中文词句与可用语音线索进行有界更新；反讽等歧义不作确定判断。效价和唤醒状态随时间回归平静，只在已授权且实际进入回复的消息上更新，不扫描旧聊天，不额外调用分类模型。支持细腻表达、明显表达、只记录、暂停感知和恢复平静。心情只影响语气与已有表情候选，继续遵守图库权限、请求模式和发送冷却，不改变事实、固定记忆或工具权限。

情绪机制参考[dsh-emotion](https://github.com/xiaoyeziyinxing/dsh-emotion)的状态、衰减与短提示设计，在小鱼侧独立实现，Codex和DSH共用。未安装该插件，不使用其跨应用全局情绪文件。运行数据与维护恢复快照均留在本机。

## 上下文衔接与定向提醒（2026-11-06）

历史按回复轮次选取：当前消息排队期间，前一轮晚落库但已投递的回答仍会带入，不带尚未处理的未来消息或失败草稿。在原有条数和字符预算内优先保留当前成员的近期线索，并记录引用、发言者和回复关系。仅合并已排队的同一成员短消息，不增加固定等待；媒体、命令、不同引用与不同成员保留边界。微信原生引用入站已接入，跨聊天或被遗忘的来源不解析为可用原文。

每群可选关闭、按需或每轮定向，默认按需，默认同一成员600秒冷却。只对当前群核验过的成员发送真实@，最多一人，只放第一条；同名无法确定时不猜，未知投递也保留冷却。QQ与微信普通/插件增强路径共用规则。微信4.2.0.13已验证独立原生@组件，含目标微信ID的回执与用户客户端提醒均确认；不通过普通“@名字”文字模拟支持。

聊天设置中可查看“上下文与@诊断”，包含选中消息编号、定向依据及实际提醒对象，不显示内部推理。313项Node回归与14项原生协议离线测试通过；Codex/DSH的隔离连续追问预览均通过；QQ真实群增强回复确认前后衔接与只首次提醒。现有固定记忆、遗忘边界和平台隔离继续生效。
