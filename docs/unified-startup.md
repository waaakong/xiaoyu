# 小鱼统一启动与服务管理方案

目标：完成一次配置后，用户日常只打开小鱼、本机Codex与QQ。小鱼统一展示和管理QQ接入与AstrBot，不再要求手动依次启动多个后台窗口。当前安装和聊天增强修复先独立完成。

## 推荐实现

1. 使用已安装服务：首次自动探测SnowLuma、NapCat、AstrBot和Codex路径，探测不到时在小鱼填写路径。保存到本机服务设置，首次配置保留官方协议确认、访问密码及QQ登录。密码不进入小鱼提示词或模型。SnowLuma官方EULA 5.4限制将专有组件并入第三方安装包、自动化部署；采用用户自己安装的原版，不重新分发组件、不自动写接受标记。
2. SnowLuma/NapCat二选一：默认沿用当前SnowLuma；可切换NapCat。切换前检查已有接入，禁止同时向同一QQ加载两个Hook。正常QQ已运行但未加载协议时，提示用户按官方流程处理，不自动退出QQ或覆盖其安装文件。
3. 启动编排：小鱼启动→复用本机Codex认证→启动OneBot监听→检查所选协议控制台和现有进程→启动用户已配置的原版服务→等待协议及QQ身份核验→按用户开关启动AstrBot。用健康检查判断就绪，不仅看子进程存在；未知的外部服务仅连接，不擅自终止。
4. 管理窗口：小鱼增加服务总览、启动/停止/重试、简明故障原因；SnowLuma/NapCat官方管理页面在小鱼独立窗口显示，维持原登录验证。AstrBot继续使用现有内嵌窗口。不能用网页嵌入绕过官方的安全策略。
5. 自动恢复：断线重新核验，限次数重启自己管理的服务；不重发旧QQ消息。退出小鱼只停止自己启动的子进程，保留用户已运行的QQ、Codex和外部实例。托盘收起继续运行，明确退出才关服务。
6. 默认不新增付费、不启用后台主动消息、不扩大授权聊天。对实际运行环境需要QQ重登或Hook加载时，显示具体原因，由用户在官方流程中完成。

## 不采用的路径

把三套组件直接塞进安装包会增加升级冲突、体积和授权问题；SnowLuma当前发行包条款也限制该做法。只嵌入管理网页则仍需用户手动启动后台，不能达到日常简化目标。推荐统一服务管理并保留独立原版安装。

## 验证与交付

先用替身进程验证顺序、端口占用、崩溃恢复、重复启动和退出归属；再用本机已有原版验证控制台可达、QQ号核验、Codex认证复用和AstrBot连通。最后在已授权私聊验证单份回复。保留原路径和配置备份，退出托管后仍可按原方式使用。

本方案不承诺无需首次登录，且不承诺普通QQ会话可以不经官方Hook加载流程直接接入。真正完成标准是重开小鱼后能恢复用户已配置的链路，或明确显示必须由用户完成的官方步骤。


## 0.14.0 使用方式

在“QQ接入 → 统一启动”点自动检测路径，选择一套协议端，保存并开启“随小鱼启动全部已配置服务”。一键启动可在不开启下次自动启动的情况下运行本次服务。AstrBot沿用小鱼已有独立环境；未安装时给出准备提示，不下载隐藏组件。

SnowLuma使用其完整包自带node.exe，保留config、登录密码、协议接受记录和hookAutoLoad设置。在官方控制台完成一次Hook加载/自动加载设置后，日常重新打开小鱼即可启动控制台和插件。当前不会代替用户勾选官方自动加载，不会关闭已有QQ。NapCat只适配现有官方Shell目录，启动方式以官方launcher.bat/napcat.bat为准，首次提权和登录仍由官方流程处理；本机未安装NapCat，不把替身测试记为真实NapCat联调。

停止托管服务会停止小鱼QQ接收、自己启动的协议控制台与AstrBot，保留QQ、本机Codex桌面程序及外部服务。停止控制台不等于从QQ卸载Hook。发现另一套控制台、已知旧协议或未就绪端口时提示处理原因，不自动改写QQ安装文件。

安装连续性已在真实AstrBot隔离副本验证：三次本地测试插件安装，中间一次失败，后续成功，无需重启；辅助模型判断、提示词注入和回复装饰也通过。模型及QQ使用替身，真实QQ收发另按授权聊天验收。
