# 小鱼依赖中心与首次环境准备方案

日期：2026-11-04。状态：用户已确认，0.15.0实现。

## 目标

在小鱼内检测所需环境、提供下载与准备入口，首次用户不必手动查找Python或运行命令。复用0.14.1的统一服务管理、独立AstrBot和按聊天授权，不覆盖现有账号、模型、人格、记忆与插件配置。不增加付费服务。

## 方案选择

推荐依赖中心：能自动准备的基础运行环境在应用内准备，需要官方首次交互的组件提供官方下载和接入入口。仅提供下载链接操作仍较多；将所有组件塞进安装包会增加体积、更新冲突，并受SnowLuma现有发行条款限制。

## 用户流程

首次配置向导增加环境检查；系统导航增加“依赖”，平时可再次检测和修复。每项显示用途、是否必需、检测版本、下载/安装/就绪状态和下一步按钮。提供“一键准备缺失基础依赖”，只准备Python与AstrBot，不下载可选语音模型、不启动QQ Hook、不启用任何聊天。

现有依赖满足时直接复用。下载和安装显示进度、当前阶段、取消与重试；失败给出可理解原因，不能一直显示安装中。准备成功后自动填入统一启动配置，用户仍可选择是否随小鱼启动。

## 下载与安装实现约束

依赖目录使用固定组件清单、固定安装目标和官方来源，不接受聊天或插件传入的任意下载URL/命令。安装启动前核对本机架构、目标路径和可写性。

官方公布校验值的下载执行对应校验；微软安装器核对签名。没有上游校验声明时只说明来源，不将自行计算的哈希声称为官方认证。保持TLS校验。Python包默认官方PyPI，提供用户明确选择的阿里云镜像；不使用隐形代理或关闭证书校验。

下载写入临时文件，成功后再提交；提取到隔离的暂存目录，拒绝路径越界。uv/Python下载清单在实现时核验并固定，不在用户启动时自动追逐最新版本。基础依赖安装串行、有总超时和取消清理，避免与AstrBot插件安装同时修改同一个环境。

AstrBot首次配置复用现有prepare-astrbot逻辑与私有网关令牌，通过标准输入传递，不写到命令行或界面日志。已有cmd_config.json和数据保留。重试后检查解释器、包版本、pip check和本机服务就绪，目录存在不等于安装完成。

## 验证与交付

用替身下载服务器和暂存目录覆盖已有依赖跳过、断网、取消、损坏文件、超时、重复点击和不覆盖已有配置。WebView2启动前检查验证缺失与已安装分支。新AstrBot环境在隔离目录做实际准备及启动验证，不重装当前联调环境。

更新首次向导、依赖页、使用说明和便携包；执行相关回归、干净副本自检与下载清单检查。最终明确哪些组件已经实际验证，哪些仍须官方首次设置。当前QQ聊天不作为安装器测试环境。

实现说明：为避免Windows的MAX_PATH限制，只有可丢弃的构建缓存使用当前用户Temp/Low下的独立短目录；Python、AstrBot和配置仍在小鱼data目录。下载源由用户选择，uv固定0.13.7并核对GitHub官方发行SHA256。
