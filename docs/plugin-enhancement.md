# 按聊天开启AstrBot增强模式

用户已确认采用每聊天独立开启；其他聊天保留小鱼原流程。目标是让聊天增强插件进入AstrBot消息、LLM请求、LLM响应、回复装饰和发送后钩子，本机Codex仍是模型来源。

## 设计与执行清单

1. 新增聊天策略pluginMode（commands/enhanced）及pluginCallLimit（1—6，默认3）；未开启增强的聊天不改变路由。小鱼管理命令仍由小鱼处理。
2. 在小鱼的已授权、已唤醒且串行排队的正常消息中创建一次性增强请求，沿用小鱼人格、带来源记忆和历史预算。一个消息只交一个主处理器，不并行让小鱼再回答。
3. AstrBot增加本机Codex Provider和流程关联适配器。采用AstrBot当前事件上下文关联随机请求ID，不从提示词猜群号，不靠全局“最后一个聊天”。仅在有效增强请求内允许模型调用；每轮计数、串行调用、时间与输入预算受限。
4. 插件可修改LLM提示、纯文本上下文及回复正文。Codex仍执行原有模型、联网权限与只读记忆召回。插件附加模型调用单独记录用量，默认每轮最多3次，不另外增加情绪分类调用。
5. 插件输出仍通过目标受限的OneBot网关；取消、聊天配置变化、账号掉线或记忆授权变化后撤销请求。投递未知不重发，已交给插件的消息超时也不再让小鱼补发第二份回答。
6. AstrBot流程完成时明确结束增强请求，释放排队；启动或连接失败时提示原因。模型调用或发送不接受过期请求ID，后台任务不因继承旧事件上下文而获得永久授权。
7. 增加界面说明、模拟模型与网关回归、AstrBot实际注册与加载验证，再在明确授权的测试聊天验收。默认不把现有聊天自动切换到增强模式。

## 首期兼容范围与边界

支持明确命令、当前事件内的普通消息钩子、纯文本人格/上下文注入、文本模型判断与回复润色。chat_plus作为集成样例，命令、判断和正常回复必须实测，安装成功不计为聊天兼容通过。

当前不支持任意AstrBot函数调用协议；模型工具仍由小鱼的Codex原生联网/记忆能力控制。不自动开放管理QQ、跨目标发送、外部模型提供方、后台定时主动发送或任意本机文件。异步脱离当前事件后才回复的聚合/定时插件需单独适配，不能一概承诺兼容。

第三方Python插件是受信任代码，不是操作系统沙箱。小鱼的输入与投递边界不能阻止插件代码自行读取用户可访问的文件或使用网络；记忆插件自己的存储与隔离策略需单独审查，不能把安装成功视作继承小鱼的记忆权限。

默认保持主聊天记忆由小鱼管理。原始聊天不批量复制到AstrBot，后续增强事件和插件输出可以被AstrBot按其配置保存；界面说明该独立存储，不虚称清空小鱼就会删除第三方插件副本。

## 连续安装与连接恢复（2026-11-04）

现有日志停在meme_manager的缺失依赖安装；AstrBot 4.29.4原实现在线程内调用pip并重定向进程标准输出，插件管理持有全局锁。不能仅凭这份日志断言是pip内部哪一处死锁。适配器通过独立pip子进程避免复用主进程pip状态，保留原参数和核心约束，240秒总超时或取消会终止自己的子进程树。下载设置180秒总期限，管理锁等待30秒返回明确忙碌提示。不会修改site-packages，也不关闭TLS。仅作用于由小鱼启动的独立AstrBot，不修改另行安装的AstrBot Launcher。

连接页和插件页增加“检查并修复连接”。运行期间每30秒检查断开的Codex与QQ账号核验；插件网关每5秒重试并检查心跳，旧请求断线撤销且不重放。用户已启动的AstrBot若意外退出，最多自动尝试启动3次；主动停止不会自动重开。不自动登录QQ，不切换QQ号，也不替代SnowLuma自身的登录流程。Codex重连沿用本机认证，不消耗生成token。

安装诊断显示下载、依赖安装及最近结果。安装成功仍需查看插件初始化结果；没有Embedding接口的记忆插件和脱离当前事件的学习/主动插件不因接入本机Codex而自动兼容。用户插件配置和独立存储保留。

## 验证方法

0.16.1起，增强模式的短中文闲聊可按模型输出的单个换行分成2—3个消息气泡，复用普通流程的判断。总长最多160字符，每条最多80字符；有空行、列表、代码或链接时保持完整。仍计入每请求3次发送的原上限，剩余次数不足时整条投递，不截掉补充内容。每条均重新核验授权、单独保存QQ回执，失败或撤销后不补发；语音合成保留该次完整文字内容。

`npm test`覆盖路由、授权、取消、调用上限、模型HTTP鉴权、连接恢复并发和管理窗口。

在已准备的独立环境运行`data/astrbot-env/Scripts/python.exe test/astrbot_provider_test.py`及`test/astrbot_installer_test.py`验证任务上下文、离线连续pip、失败后恢复、超时及取消。

`node scripts/verify-enhancement.mjs`启动隔离AstrBot副本与真实chat_plus；模型与QQ为替身。检查辅助判断、提示词注入、回复装饰、一条消息单份回复，并在同一进程连续安装本地测试插件、制造一次失败后再安装，不下载或安装真实外部依赖。测试结果写入被Git忽略的data。

本机后续诊断发现官方PyPI列表可读，但minio的元数据下载连续超时；改用阿里云镜像后下载成功，minio wheel的SHA256与官方PyPI JSON元数据一致。已备份并仅调整当前AstrBot的索引URL，安装minio/tqdm后pip check通过。新环境仍默认官方PyPI，可在AstrBot配置中按实际网络选择索引。

0.14.1补充：模型权限绑定正在执行该消息流水线的asyncio任务，不能仅凭继承的ContextVar在后台派生任务调用模型。并行后台学习不会抢占本轮主回复；主动学习/Embedding仍需独立适配。当前Codex要求app-server启动提供方与线程一致，HTTP传输覆盖改为独立进程启动参数，保留用户全局配置和认证不变。模型内部错误不会作为正常插件文字投递到QQ。
